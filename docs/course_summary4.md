# 实验报告：中间代码生成模块 (IR Generation)

## 一、 设计目标
在语义分析成功的基础上，本阶段的任务是将抽象语法树（AST）转化为平台无关的线性三地址码（Three-Address Code, 3AC）。设计目标是保持编译器架构的解耦性，通过增量开发实现对基本表达式、赋值语句、控制流结构及函数调用的支持。

## 二、 系统架构与数据结构
本阶段引入了 `ir.h` 与 `ir.c` 两个核心模块，将中间代码生成与 AST 遍历逻辑独立分离。

### 1. 指令集模型
采用双向链表存储三地址码指令（`InterCodes`），每条指令包含操作码（Kind）及操作数（Operand）。支持的指令类型包括：
* **计算指令**：`ASSIGN`, `ADD`, `SUB`, `MUL`, `DIV`
* **控制流指令**：`LABEL`, `GOTO`, `IF_GOTO`
* **函数交互**：`FUNCTION`, `PARAM`, `ARG`, `CALL`, `RETURN`

### 2. 核心辅助机制
* **临时变量生成器 (`new_temp`)**：按序生成 `t0, t1, ...`，用于承载复杂表达式的中间计算结果。
* **标签生成器 (`new_label`)**：按序生成 `label0, label1, ...`，用于实现控制流跳转的靶点。

## 三、 核心实现逻辑
中间代码生成采用递归遍历 AST 的方式，主要通过以下两组函数驱动：

### 1. 表达式翻译 (`translate_exp`)
采用“基于传递（Place-based）”的策略。通过传入一个 `Operand* place` 参数，将表达式的计算结果存入该位置。
* **算术运算**：递归计算左右子树，生成新临时变量，并将双目操作符转换为对应的 IR 指令。
* **赋值运算**：处理 `Exp -> ID ASSIGNOP Exp`，递归处理右侧表达式并将结果赋值给左侧变量。

### 2. 语句与控制流翻译 (`translate_stmt` / `translate_cond`)
* **基本语句**：直接驱动表达式翻译。
* **控制流 (`if`/`while`)**：采用短路求值策略。通过 `translate_cond` 函数，根据条件表达式的真假值决定跳转目标（True Label 或 False Label），从而避免了计算复杂的逻辑运算结果，极大简化了控制流的翻译。

## 四、 测试与验证
通过 `test/test_ir.cmm` 对编译器进行了功能性验证：
* **赋值语义**：验证了变量存取与基本算术表达式的正确映射。
* **控制流逻辑**：验证了 `IF` 和 `WHILE` 结构下标签跳转的逻辑一致性。
* **集成测试**：通过 Makefile 的 `test` 目标，实现了从语法分析到中间代码生成的全链路自动化测试，IR 输出符合标准三地址码规范。

## 五、 问题与改进方向
在实验过程中，通过 `gdb` 定位并修复了 AST 构建过程中的空指针解引用问题，确保了流水线的稳定性。后续的优化方向包括：
1. **数组与结构体支持**：目前仅支持基础变量，未来需扩展 `DEC` 指令和地址运算指令 (`GET_ADDR`)。
2. **基本块优化**：利用已生成的双向链表结构，进一步实现死代码消除（Dead Code Elimination）与常量折叠。
3. **函数调用栈管理**：完善实参列表（`ARG`）的序列化处理。
